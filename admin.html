Cara 1: Ekstensi browser Direkomendasikan · Tanpa baris perintah · Semua platform

Gunakan ekstensi browser kecil untuk menyinkronkan status login muse.ai yang sudah masuk di komputer Anda sendiri. Tidak perlu memasang Python, membuka terminal, atau mengetik perintah.
Mengapa harus memakai ekstensi: cookie sesi login muse.ai bertanda httpOnly tersebut, skrip halaman web (mengetik document.cookie di F12, bookmarklet) tidak dapat membacanya; hanya antarmuka cookies ekstensi browser yang bisa mengambilnya.
1
Unduh dan ekstrak ekstensi
Ekstrak ke direktori yang tidak akan Anda hapus, misalnya D:\muse2api-extension.
⬇ Unduh muse2api-extension.zip
2
Muat ekstensi di browser
Contoh memakai Chrome (langkah untuk browser berbasis Chromium seperti Edge / Brave / 360 serupa):
  1. Ketik chrome://extensions di bilah alamat lalu tekan Enter
  2. Nyalakan sakelar Mode Pengembang di kanan atas
  3. Klik Muat ekstensi yang telah diekstrak di kiri atas
  4. Pilih folder hasil ekstraksi dari langkah 1 (bukan berkas tunggal di dalamnya)
3
Masuk ke muse.ai, lalu klik ikon ekstensi untuk mengimpor
Buka https://muse.ai/ di browser Anda sendiri dan masuk (sampai terlihat antarmuka chat), lalu klik ikon ekstensi di bilah alat browser, Isi kedua item di bawah, lalu klik "Baca dan Impor".

Cara 2: Salin manual Tanpa instalasi · Cadangan

Jika tidak ingin memasang ekstensi, Anda bisa mengambil string cookie secara manual. Kuncinya adalah memakai header permintaan di panel "Jaringan", bukan Console — baris cookie: di header permintaan berisi cookie httpOnly tersebut, yang tidak bisa dibaca Console.
  1. Buka dan masuk ke https://muse.ai/ di browser Anda sendiri, berhenti di antarmuka chat
  2. Tekan F12 untuk membuka alat pengembang, beralih ke panel Jaringan / Network
  3. Tekan F5 untuk memuat ulang halaman agar daftar permintaan muncul
  4. Klik salah satu permintaan muse.ai di daftar (yang pertama pun boleh)
  5. Di sisi kanan, temukan Header / Headers → gulir ke bawah ke Header Permintaan / Request Headers
  6. Temukan baris yang diawali cookie:, salin seluruh string setelah titik dua (mulai dari hatch_sess= sampai akhir baris)
  7. Tempel ke kolom input "Cara 3" di bawah, lalu klik impor
Perhatian: yang dipakai adalah cookie: di header permintaan, bukan "header respons". set-cookie di header respons hanya berisi sebagian cookie, akan ada yang hilang.

1. Model yang tersedia

ID ModelKegunaanAPI

POST /v1/responses
muse-imageTeks ke gambar / edit gambarPOST /v1/images/generations

Ketiga ini adalah kemampuan nyata seri Muse: Muse Spark (bahasa / kode), Muse Image (buat gambar), Muse Video (buat video). Halaman web muse.ai adalah agent dengan routing otomatis, antarmukanya tidak memiliki pemilih model, Jadi kolom model hanya untuk kompatibilitas downstream — mengirim gpt-4o, claude-sonnet-4, dall-e-3 dan nama umum lainnya akan otomatis dipetakan ke kemampuan yang sesuai.

2. Obrolan / tulis kode

Salin
# Non-streaming
curl -X POST "BASE/v1/chat/completions" \
  -H "Authorization: Bearer $MUSE2API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"muse-spark","messages":[{"role":"user","content":"Tulis quicksort Python"}]}'

# Streaming: tambahkan "stream":true, mengembalikan SSE standar (data: {...} / data: [DONE])

3. Buat Gambar (curl)

# Respons
{"created":1790148495,"data":[{

5. Python (kompatibel openai SDK)

Salinfrom openai import OpenAI
import time

client = OpenAI(base_url="BASE/v1", api_key="m2a_...")

# Buat Gambar
r = client.images.generate(model="muse-image", prompt="Seekor anjing Shiba memakai helm astronot")
print(r.data[0].url)

# Buat Video (memakai endpoint native, karena ini tugas asinkron)
import requests
t = requests.post("BASE/v1/videos", json={"prompt":"Anak kucing berjalan","duration":5},
                  headers={"Authorization":"Bearer m2a_..."}).json()
while True:
    s = requests.get(f"BASE/v1/videos/{t['id']}",
                     headers={"Authorization":"Bearer m2a_..."}).json()
    if s["status"] in ("succeeded","failed"): break
    time.sleep(5)
print(s)

7. Autentikasi

Selain /healthz, /readyz, dan /v1/media/*, semua API lain memerlukan Authorization: Bearer <API Key>. API Key dikonfigurasi di server pada MUSE2API_KEY di /opt/muse2api/.env.

8. Menghubungkan berbagai klien / agen

Klien apa pun yang mendukung "endpoint kompatibel OpenAI kustom" hanya perlu mengisi tiga nilai:
Item pengaturanIsi apa

API Keym2a_... (yang ada di "Info integrasi" di bagian atas halaman ini)

Nama model apa pun bisa dipakai: nama umum (gpt-4o, gpt-5, claude-sonnet-4, deepseek-chat, gemini-2.5-pro, dll.) akan otomatis dipetakan ke kemampuan yang sesuai; nama yang sama sekali belum dikenal akan diteruskan apa adanya, muse.ai memang memakai routing otomatis, Tidak memengaruhi hasil.

Kompatibilitas berdasarkan jenis klien

Jenis klienKemampuan yang dibutuhkanStatus
Obrolan / chat (desktop, Web UI, plugin browser)POST /v1/chat/completions✅ Tersedia
Output streaming (efek mesin tik)stream:true (SSE standar)✅ Tersedia

Klien pembuatan videoPOST /v1/videos (polling asinkron)✅ Tersedia
Mode agen otonom yang membutuhkan "pemanggilan alat"tool_calls / function calling⚠️ Tidak tersedia
Tentang batasan "pemanggilan alat" ini (penting, sudah teruji):
Asisten web muse.ai memiliki kebijakan penolakan alignment yang jelas terhadap "output JSON pemanggilan alat palsu" — kalimat asli yang teruji adalah "Saya tidak akan mengeluarkan 'pemanggilan alat palsu' dalam format JSON seperti ini — saya tidak punya alat get_weather". Mencoba adaptasi dengan tiga protokol prompt yang berbeda kata dan posisi, semuanya gagal.
Jadi: mode Agen otonom yang bergantung pada tool_calls (yang otomatis membaca-menulis berkas, menjalankan perintah, dan sejenisnya) tidak bisa diintegrasikan; Tetapi semua penggunaan gaya tanya-jawab — percakapan, menulis kode, penjelasan, penerjemahan, ringkasan, buat gambar, buat video — semuanya sepenuhnya tersedia.
Jika klien tetap memaksa menyertakan kolom tools, API tidak akan error, melainkan mengabaikan deklarasi alat dan menjawab seperti percakapan biasa.

Proxy akun

Browser, pemeriksaan sesi, dan keep-alive akun ini memakai proxy yang sama. Kegagalan proxy akan dilaporkan sebagai error, tidak otomatis beralih ke koneksi langsung.

Tempel langsung tautan HTTP, SOCKS5, atau SOCKS5h yang berisi nama pengguna dan kata sandi, lalu uji segera, tanpa perlu menyimpan dulu.

Isi info autentikasi secara manual (opsional)

Kata sandi tidak ditampilkan kembali. Jika alamat dan nama pengguna tidak berubah, kosongkan untuk mempertahankan kata sandi tersimpan; setelah mengubah alamat atau nama pengguna, masukkan ulang kata sandi.

Saat akun sedang menjalankan tugas, ubah proxy nanti. Setelah disimpan, permintaan berikutnya memakai pengaturan baru.
